# Because fields are accessed by name at runtime, working with instance state is slow. It’s technically a constant-time operation—thanks, hash tables—but the constant factors are relatively large. This is a major component of why dynamic languages are slower than statically typed ones.
# How do sophisticated implementations of dynamically typed languages cope with and optimize this?

Modern dynamic language implementations use several optimization techniques to make field access faster. A common strategy is hidden classes, where objects with the same set of fields share structural information. This allows field access to behave more like indexing into an array rather than performing a full hash table lookup. Another common optimization is inline caching, where the runtime remembers the result of previous field lookups and reuses that information when similar accesses occur again. Just-in-time compilers can further optimize field accesses by generating specialized machine code based on observed object layouts. These techniques allow dynamic languages to retain flexibility while significantly reducing the runtime cost of property access.
