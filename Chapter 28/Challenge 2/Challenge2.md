# In a dynamically typed language like Lox, a single callsite may invoke a variety of methods on a number of classes throughout a program’s execution. Even so, in practice, most of the time a callsite ends up calling the exact same method on the exact same class for the duration of the run. Most calls are actually not polymorphic even if the language says they can be.
# How do advanced language implementations optimize based on that observation?

Advanced implementations often use a technique called inline caching. The idea is that most call sites repeatedly invoke the same method on objects of the same class. Instead of performing a method lookup every time, the runtime stores the previously resolved class and method at the call site. When the same call occurs again, the runtime can reuse the cached method directly. More sophisticated systems extend this idea with polymorphic inline caches and just-in-time compilation to further reduce method lookup overhead. These optimizations exploit the fact that real programs are often less dynamic than the language semantics allow.
