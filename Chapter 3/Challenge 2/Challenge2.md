# This informal introduction leaves a lot unspecified. List several open questions you have about the language’s syntax and semantics. What do you think the answers should be?


Numeric types — Is there one numeric type, or separate integers and floats? I'd guess a single double-backed type, since the spec never mentions integer-specific behavior like overflow. What happens with 1 + "2"? I'd expect a runtime error rather than implicit coercion, since silent type conversion tends to cause confusing bugs. Equality across types — Is 1 == "1" true or false? I'd guess always false. Comparisons across types should be well-defined but never equal, like strict equality rather than loose equality.  Are 0 and "" falsy? I'd guess only nil and false are falsy, with everything else truthy. A simpler rule than treating "empty" values as false. Is scoping lexical or dynamic? I'd expect lexical scoping, since that's standard in modern languages and makes closures predictable. What does var x; evaluate to? Likely nil, matching most dynamically-typed languages. Exceptions, or does an error just halt the program? I'd guess it just prints a message and stops, since full exception handling adds complexity.
