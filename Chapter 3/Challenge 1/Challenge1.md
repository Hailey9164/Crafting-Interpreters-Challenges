# Write some sample Lox programs and run them (you can use the implementations of Lox in my repository). Try to come up with edge case behavior I didn’t specify here. Does it do what you expect? Why or why not?


I tested several arithmetic edge case behaviors. Division by zero (10 / 0, -10 / 0, 0 / 0) returned Infinity, -Infinity, and NaN instead of crashing. This makes sense since jlox represents all numbers as Java doubles, so it inherits Java's IEEE 754 floating-point behavior without needing special-case handling. Mixed-type addition ("1" + "2") concatenated to "12" rather than adding numerically. Equality across types (0 == false, "" == false) both evaluated to false. !0 and !"" both evaluated to false, meaning 0 and "" are truthy in Lox, unlike many C-like or Python-like languages. Every result matched my expectations once reasoned through: Lox has no implicit coercion and represents all numbers as doubles. What looked surprising at first turned out to be predictable consequences of those two design choices.
