# Our simple local array makes it easy to calculate the stack slot of each local variable. But it means that when the compiler resolves a reference to a variable, we have to do a linear scan through the array.
# Come up with something more efficient. Do you think the additional complexity is worth it?
The compiler could store local variables in a hash table instead of a simple array. This would reduce variable lookup from a linear search to approximately constant time because the compiler could directly find a local variable by name instead of scanning through all locals in scope. However, local variable resolution happens only at compile time, while the resulting bytecode may execute many times. Since compilation is performed relatively infrequently and the number of local variables in a scope is usually small, the existing linear scan is often fast enough. A hash table would improve lookup performance but would also add complexity and require additional memory. Personally, I do not think the optimization is worth it for most programs because the benefit would likely be small compared to the added implementation complexity.
