# Other languages, like Ruby, do allow classes to be modified after the fact. How do implementations of languages like that support class modification while keeping method resolution efficient?

Languages that allow classes to be modified after they are defined must ensure that cached method lookups remain valid. One approach is eager propagation, where changes to a superclass immediately update all subclasses. Another approach is lazy invalidation, where classes track version numbers and rebuild inherited methods only when needed. A third option is to use inline caches and invalidate them whenever a class changes. Of these approaches, I think inline cache invalidation is the most practical because it preserves fast method dispatch during normal execution while only paying extra cost when metaprogramming occurs.
